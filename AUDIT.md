# Аудит метеодашборда zapovednik-hack — отчёт

Версия методики `2026.11.1`. Правила сверены с README фактического архива
(`meteo_clgz_hackathon`), кейсом и эталонной реализацией. Расчётное ядро вынесено
в пакет `meteo/`, единая реализация правил используется агрегатами, журналом
качества и выгрузкой Excel.

## Ручная сверка (реальные CSV)

- **День.** Кр1, температура, 01.01.2024 (`kr1_2024.csv`, строки 2–49): 48 пригодных
  значений за 24 разных часа; сумма −762,91 ÷ 48 = **−15,89395833333333 °C**.
  Получено −15,893958333333332 °C (совпадает до представления float).
- **Месяц.** Кр1, температура, январь 2024: сумма 31 суточного среднего
  −328,65150458680234 ÷ 31 = **−10,60166143828395 °C**, 31 пригодный день.
  Получено −10,601661438283946 °C.
- **Давление Кр1 2024.** 363 дня станции, 334 дня давления, 11 месяцев,
  **1 362 флага `pressure_hpa:range`** (апрель не входит в месячное давление).
  Получено 363 / 334 / 1 362.
- **Сравнение Кр1 и Кр2, январь 2025.** Разность по 31 общему пригодному дню:
  **−0,1853225806 °C**. Получено −0,18532258064516127 °C.
- **Покрытие.** 420 строк совпали с `coverage_by_month.csv` (0 расхождений).
- **Строки.** 874 560 исходных, 874 488 пригодных, 72 конфликтных — совпало.

## Команды запуска

```powershell
py -3 -m meteo.verify                        # сверка с эталоном
py -3 -m meteo.build_json                    # регенерация series.json / exceptions.json
py -3 -m meteo.serve --port 8501             # статика web/ + JSON/Excel API
```

## Сценарий демонстрации

1. Открой `http://127.0.0.1:8501/landing/dashboard`.
2. Шаблон «Давление и качество»: Кр1, давление, 2024. Апрель — разрыв в месячном ряду.
   Журнал исключений показывает 1 362 значения `pressure_hpa:range` (например 770,1 гПа),
   клик по сроку ведёт к файлу и строке.
3. Шаблон «Поляна и поле — температура»: Кр1 и Кр2, 2025, разность по общим суткам.
4. Добавь линию (значение 0) — она рисуется на графике.
5. «Выгрузка в Excel» — `.xlsx` с тремя листами.
6. В отдельном экземпляре: `POST /api/import` с `kr2_2025.csv` → предпросмотр и
   подтверждение; повторный файл не увеличивает выборку.

## Проверено фактически

- Корректность агрегатов, покрытия и QC — сверено с эталоном (все числа выше).
- Сквозной путь CSV → допуск → полнота → агрегат → график → Excel (сервер отдаёт
  статику, JSON API и `.xlsx`; smoke-тест прошёл: meta/compare/raw/export).
- Роза ветров и среднее направление (359°+1° → 0°; 90°+270° → не определено).
- Догрузка CSV (предпросмотр/подтверждение, повтор не дублирует) — реализована в API.

## Ограничения (осталось)

- Фронтенд переведён на корректную схему и основные исправления; шаблоны
  «Воздух и почва по глубинам» (амплитуда/задержка максимума), «Температура и
  влажность» (двухосевые панели) и вертикальные метки/полосы/температурные
  переходы (РД 52.33.725-2010 § 6.1.2) реализованы частично или в дорожной карте.
- Импорт CSV через браузер (drag-and-drop) не подключён — доступен через API
  `POST /api/import`; браузерный UI догрузки — следующий шаг.
- Хранение — in-memory + повторный разбор при догрузке; для многоэкземплярной
  работы целесообразен SQLite/DuckDB (схема и SQL эталонной реализации в
  `.reference/`).
- Почасовой суточный ход Кр1/Кр2 (общие пары «дата + час») — в ядре, не выведен
  на экран.
